# healdan-web

Guidance for the User app and the Admin app. It was moved out of the root `CLAUDE.md`, so that it loads only when Claude works on files here. The root file still applies, and its "Where the rest lives" lists the other files like this one.

- The API the apps call is in `healdan-api/CLAUDE.md`, and the records and services behind the Admin app's screens in `healdan-core/CLAUDE.md`. The browser specs and how `smoke-test.sh`'s step 9 runs them are in `docker/CLAUDE.md`.
- `healdan-web` builds the User app and the Admin app (`healdan-web/web`, an npm workspace) through `frontend-maven-plugin`, which downloads Node into `healdan-web/target/` (the version in `.nvmrc`, which the POM names too: change both, as `scripts/workspace.test.mjs` fails until they match) and runs `npm ci --ignore-scripts` and `npm run build` in `generate-resources`; `maven-resources-plugin` then copies `apps/user/dist/` into the jar's `healdan/app/user`, which `AppServlet` serves, and (`copy-admin-app`) `apps/admin/dist/` into `healdan/app/admin`, which `AdminAppServlet` serves. `-Dhealdan.web.skip=true` skips Node, and each copy then does nothing when its `dist/` doesn't exist, so the jar holds no app and `/app/` answers 503, as `/admin/` does an administrator. CI's `build` check passes it everywhere; the `Web` check and the Docker build do the Node build (the Dockerfile keeps npm's cache in a mount).
  - The workspace's `.npmrc` sets `ignore-scripts` and `save-exact`, so a developer's own `npm install` runs no package's install script either and pins what it adds (`scripts/workspace.test.mjs` checks both).
- **`healdan-web`** is the User app, Healdan's browser app at `/app/`, and the Admin app at `/admin/` (JPF id `healdan-web`; M6's spec is `docs/superpowers/specs/2026-11-10-m6-user-app-design.md`, the Admin app's `docs/superpowers/specs/2026-11-18-admin-app-design.md`). Its Java is `com.logicaldoc.healdan.app`: `AppServlet` (`@WebServlet("/app/*")`) serves the built app from the jar, answering any path that isn't a file the jar holds or under `assets/` (so `/app/doc/10388.2` too) with `index.html`, and, with no web session the API would accept (`WebSessionRoute.session` and `user`), stores the return path (`ReturnPath`, accepted only in a strict form, else `/app/`) and redirects to `login.jsp`. A signed-in page load forgets the return path. The apps are the npm workspace `healdan-web/web` (React, TypeScript, Vite; `packages/api` typed from `openapi.yaml` and `openapi-admin.yaml`, `packages/ui` with the components, colour tokens and string catalogue, `packages/shell`, `apps/user`, `apps/admin`). Only the root context is supported. Their code talks to `/api/v1` only, through the same-origin web-session route (see `healdan-api/CLAUDE.md`), never with a token.
  - `packages/shell` (`@healdan/shell`) holds what both apps need that depends on TanStack Query or the API: `useApi`, the query client, the signed-out state, `messageFor(error, catalogue?)` and `fieldErrors`, `MessagesProvider` and `useMessageFor()` (an app with a catalogue of its own wraps its tree in the provider, so the shared components say problems in its words: the Admin app's `App` does, with `problemLookup`), the person and Help menus, the mark, the signed-out, insecure-address and `NoAdminAccess` pages, `parseSearch`/`stringifySearch`, `preferences(prefix)` (the User app's prefix is `healdan.`, each app's its own) and the shared queries. It registers no router. The User app's `queryClient.ts`, `services.tsx`, `signedOut.ts`, `queries.ts` and `frame/errors.ts` re-export what moved from them. `npm run typecheck` is `tsc -p . && tsc -p apps/user && tsc -p apps/admin`, as each app registers its own TanStack router, which one program can't hold twice, and ESLint's `healdan/no-app-imports-another` (`eslint.config.js`) refuses one app importing another's code; `scripts/workspace.test.mjs` checks both. Both apps' Vite `publicDir` is `packages/ui/public/`, which holds `pressable.css`.
  - `scripts/file-kinds.test.mjs` reads `healdan-core`'s `FileKinds.java` and the catalogue (`packages/ui/src/strings/en-US.ts`), and fails unless `FileKinds.BY_NAME`, the order the server sorts File Type by, is the `filters.type.*` names A to Z, as the browser sorts a one-page list: a name changed there changes `BY_NAME` too.
  - `scripts/check-dist.mjs` takes the app (`node check-dist.mjs admin` in the Admin app's `build`, none for the User app's): it fails when any file of the User app's build holds `admin.dashboard.title` (`ADMIN_MARKER`, a key of the Admin app's catalogue) and when the Admin app's build has PDF.js or lacks the marker.
  - The Admin app is `apps/admin` (`@healdan/admin`), with its own catalogue (`apps/admin/src/strings/en-US.ts`, every key `admin.`, through `@healdan/ui`'s `createCatalogue`), router (basepath `/admin`; `addresses.ts`, which `addresses.test.ts` checks against spec §6.3's forbidden segments) and test helpers (`test/renderApp.tsx`, `test/fakeApi.ts`). No PDF.js. `AdminAppServlet` (`@WebServlet("/admin/*")`) and `AppServlet` share `BuiltAppServlet` (methods, headers, path parsing, media types, hashed files, ETags). `AdminAppServlet` asks before it reads the path whether the web session's user (`WebSessionRoute.session` and `user`) is in `admin` (`AccessChecks.isAdmin`), at every request: signed out, a page stores the return path and redirects to `login.jsp`, and a file (decided by the path alone: under `assets/` or a build extension) is an empty `401`; signed in and not an administrator, every path is the same `403` with the User app's `index.html` (plain text if it isn't built), the return path forgotten, whose `main.tsx` draws only `NoAdminAccess` at an `/admin` address; an administrator gets `index.html` or the file, or `404`; and a check that fails (a database that doesn't answer) is the same `no-store` `503` for every path, a line of plain text to try again, the return path kept. Hashed files are `private, max-age=31536000, immutable`; the page and every refusal `no-store`, set explicitly, as CE's `CacheControlFilter` would leave `max-age=600` on a refused `.js`. Its policy is `AppServlet`'s with `worker-src 'none'`, its `frame-src 'self'` kept for the downloads' hidden frame (`AdminAppServletTest` checks the text, and that the worker is all it takes away). Answers use `setStatus`, never `sendError`.

  - A filed email is read through `healdan-api`'s `MessageResource` (`/v1/documents/{n}/message`, `/body`, `/parts/{id}` and `/attachments/{id}/file`; spec §6.6, §9.4), `eml` and `msg` alike (`healdan-core`'s `StoredMessage`). `EmailBody` cleans the HTML with jsoup (`Safelist.relaxed()` plus styling, with every `url()`, `@import` and CSS escape taken out), embeds `cid:` pictures as `data:` up to 2 MiB, and removes internet pictures unless `pictures=true`. The `/body` page carries its own `Content-Security-Policy` (`EmailBody.policy`), and the app shows it in an `<iframe sandbox="allow-popups allow-popups-to-escape-sandbox">`, never with `allow-scripts` or `allow-same-origin`. Every answer that serves stored bytes inline (`/preview`'s pictures, `/parts/{id}?inline=true`) carries `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox`. `AppServlet`'s policy stays as it is. A `msg` keeps no Content-IDs (CE's reader), so its inline pictures are attachments.
  - Filing is `apps/user/src/filing/` (spec §6.5): `FilingProvider` in the frame owns an in-memory upload queue (three at once, kept across views, `beforeunload` while it runs), the form that comes first (`details/FieldsForm.tsx`, shared with `PropertiesForm`) and the tray (`@healdan/ui`'s `Tray`, a top layer). It handles only drops that carry `Files`; a drop that carries `ROWS_TYPE` (`application/x-healdan-documents`, the app's own rows) is for the move to take. A drop on a document's row asks for a new version, which goes through `saveVersion` (shared with Check In), never taking over a hold (R14).
  - Below 1,024 pixels (`@healdan/shell`'s `frame/narrow.ts`) the left pane and the right region fold away behind top-bar buttons (**Navigation**, **Details and Filters**) and open over the list, where Esc closes them; a click on a row never opens the region (`open('details', { reveal: false })`). **Signed-in Devices** (`devices/SignedInDevices.tsx`, from the person menu) lists `GET /v1/auth/tokens` with Revoke, and the web page's own sign-in isn't in it (R14). The Upload button, pressed with Option, shows the filing form first: the keyboard's route to it.
  - The old UI links to it with **Open in Healdan**, a hook in `MainMenu` (`HealdanAppLink`, an upstream edit listed in M6's spec §14.1), and the app links back with **Classic Interface** (`frontend.jsp`, same session). `ui.start` (`app` or `classic`) decides where a plain sign-in lands.

## Tests

- `healdan-web`'s `AdminAppServletTest` extends `AbstractHealdanTestCase` too, signing real people in to CE web sessions on the test database, so `healdan-web`'s tests need the PostgreSQL and `healdan-core` installed with its test-jar. Its `context.properties` is copied from `../healdan-core/src/test/resources` as `healdan-api`'s is, its test classpath is `healdan-api`'s (`HealdanContext`'s scan finds the API's beans), and `healdan.secretKey` is under `target/`. `AppServletTest` needs no database. Both serve fixture builds under `src/test/resources/healdan/app/`, and `AppServletTest#testNeverReachesTheAdminApp` checks no `/app/` path reaches `healdan/app/admin/`.
