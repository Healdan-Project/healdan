# Clients

Guidance for the Healdan Helper, the LibreOffice extension and the Office add-ins. Their CI (`clients.yml`, the helper's releases) is in `.github/CLAUDE.md`. It was moved out of the root `CLAUDE.md`, so that it loads only when Claude works on files here. The root file still applies, and its "Where the rest lives" lists the other files like this one.

- **Healdan's clients** live under `clients/`: the Healdan Helper (`clients/helper/`, .NET 10), the LibreOffice extension (`clients/libreoffice/`, Python with UNO and the standard library only) and the Office add-in (`clients/office/`, JavaScript with no dependencies). The Developer Guide's Desktop Clients page (`site/content/developer/desktop-clients.md`) has how they work: the cycle, the local copies, the channel and its routes, the add-in and its port. M3's spec is `docs/superpowers/specs/2026-10-24-m3-office-integration-design.md`, M3.5's (Microsoft Office on the Mac) is `docs/superpowers/specs/2026-10-30-m3-5-microsoft-office-design.md`, and M3.6's (PDFs in CoffeePDF) is `docs/superpowers/specs/2026-11-01-m3-6-pdfs-in-coffeepdf-design.md`.
  - The Office add-in is classic scripts, not ES modules, with its logic in `healdan.js` (which also loads under Node) and the Office.js calls in `office-glue.js`. `healdan-api` packages `clients/office/` into its jar, and `AddinResource` serves the pages and a manifest made with the server's own address, public, at `/api/addin/`. That isn't JSON API, so `openapi.yaml` and `RouteCoverageTest` leave it out.
  - Outlook (M5, new Outlook for Mac) is a second add-in: `AddinResource` serves `outlook-manifest.xml`, made from `clients/office/outlook-manifest.template.xml` (read/write mailbox permission; Mailbox 1.14 required, for `getAsFileAsync`, so an Outlook without it doesn't show the add-in; no `SupportsMultiSelect`, since the trial found `loadItemByIdAsync` absent), and the pane is `web/mail.html`, `mail.js` (the logic, Node-testable) and `mail-glue.js` (the Office.js calls). It adds "Healdan" to the mailbox's category list before tagging a message, since Outlook refuses a category the list lacks, and works only in the primary mailbox. It holds no token and calls only the helper.
  - The helper pairs Outlook by name (`Pairing.OutlookName`), not as an `OfficeProgram`, as it isn't in the copy cycle. Its keyed mail routes (`AddinServer.KeyedRoutes`, Outlook's key only) are `mail/status` (never pends; 1 to 100 Message-IDs, of which the helper asks the server about 21 at most, within 6,000 characters), `mail/file` (File Here with a `folderId`, or the Save window's email mode, opened at `openAt`); phase 2's several messages add `mail/file-many` and `mail/file-one` with the plan's Task 13. Outlook's key is refused on the document routes but `result`, as the other keys are on the mail routes. The helper's `MessageIds` normalises a Message-ID as the server's does, to the character, or a filed message shows Not Filed. A message over `upload.maxsize` (100 MB on a new install) is `409 over-upload-limit`, a code of its own, as the port's `413` is the helper's own 150 MiB body limit. The logic is `Healdan.Helper.Core`'s `Mail/` (`MailFiling`, `Suggestions`) and the window `SaveWindow.Email.cs`. M5's spec §9.5 holds the trial's findings on new Outlook for Mac.
  - `IOfficeScripting` is the seam that drives Word, Excel and PowerPoint: AppleScript lives only behind it, and every value goes in through `on run argv`, never into a script's text. `MacOfficeScripting` is its macOS implementation, and `SaveAs` never takes the front window.
  - The helper serves the add-in over HTTPS on loopback (`Addin/`, ports 47615 to 47618) with its own self-signed certificate, which Set Up Microsoft Office asks macOS to trust, and each Office app pairs once, by a code the helper shows. The port lives as long as the helper, signed in or not, and only Set Up renews the certificate. A route still running after 20 seconds answers `202`, and the add-in collects its outcome through `result`.
  - On macOS, CoffeePDF ([coffeemuse/CoffeePDF](https://github.com/coffeemuse/CoffeePDF)) is the app for PDFs while it's installed with Healdan support on, which `CoffeePdfSettings` reads from its `settings.json` (`healdan.enabled` must be `true`) at each choice; otherwise a PDF opens read-only in the default app. Its lock file is `.~coffeepdf.<copy file name>#`, and it saves by writing a temporary file and renaming it over the copy. `CopyNames.AppFiles` lists every app's lock and owner files, for deleting, renaming and setting copies aside, and `IsAppFile` recognises them separately, for the stray sweep, so a new app adds its names to both (its own `LockExists` names its lock as well).
  - Put anything testable in `Healdan.Helper.Core`, which has no windows and which `Healdan.Helper.Core.Tests` drives, the extension's logic in `healdan_logic.py`, which the tests run without LibreOffice, and the Office add-in's in `clients/office/web/healdan.js`, which has no Office or page in it and which Node's test runner drives. The app's own code that needs Avalonia to test goes in `Healdan.Helper.Tests`, which runs Avalonia headless with Skia's drawing and the helper's own styles, so a test can make a window and click it (`SetUpOfficeWindowTests`).
  - On macOS the helper's text is San Francisco, which Avalonia 12 measures at the font's default instance (Display) while Skia draws it at Text size. `Platform/SystemFont.cs` wraps Avalonia's HarfBuzz shaper in a `DispatchProxy` (Avalonia's reference assemblies block implementing `ITextShaperImpl`) that sets the drawn instance and each run's point size. It reaches `HarfBuzzTypeface.HBFont` and `SkiaTypeface.SKTypeface`, internal to Avalonia, so an Avalonia upgrade must keep `SystemFontTests` (macOS only, against CoreText's widths) passing.
  - On macOS the helper never runs `unopkg`, which can't install the extension there: it opens its `.oxt` in LibreOffice for the user to accept. On Ubuntu it runs `unopkg` only at a start with LibreOffice closed, and otherwise LibreOffice asks the user. On both systems it reads LibreOffice's user registry (`ExtensionCheck`; `~/.config/libreoffice/4/user` on Ubuntu) as the menu opens and every few seconds while the extension is missing, so it sees one the user accepted while it ran. A Mac's start reads it; on Ubuntu a start reads it only while LibreOffice is open (with it closed it's `unopkg list`, and a helper version already checked with the extension current reads nothing).
  - One helper runs per user on both systems: `Program.Main` holds a lock file, `helper.lock` (`SingleInstance`), in the helper's folder (`$XDG_DATA_HOME/healdan-helper/` or `~/.local/share/healdan-helper/` on Ubuntu), and a helper that can't open it starts anyway, logging that. A helper whose `channel.json` names a live process (on Ubuntu, the user's own) whose channel answers counts too, on both systems: one from before the lock, or one that couldn't open the file. So on macOS a second copy started for a link while the first is still signing in hands the link over, once, and quits, instead of starting a second full helper. On Ubuntu the desktop entry runs `HealdanHelper %u`: the first start takes its link from its arguments and holds it until signed in, and a second process hands each link to the running helper with `POST /v1/link` (`LinkHandOver`), waiting up to 30 s for one still starting (and never sending again one that got no answer in time), then quits. A link waiting longer is dropped, with a log line and a notice naming its doc #; a second start with no link says the helper is already running, and a `healdan:` link that isn't an open link says it was ignored. The session accepts links before its channel starts, and opens the held one once it listens.
  - On Ubuntu, notices go through `notify-send` (`NotifySend`) off the caller's thread, in order, the keychain is `secret-tool` with a 2-minute limit, and the default app is `xdg-open`, whose refused kinds also include Linux's and Wine's runnable ones. Crash detection counts only the user's own `soffice.bin` processes (`OwnProcesses`, from `/proc`: the user's uid, in the helper's pid namespace, not zombies), so another user's or a container's LibreOffice can't hide a crash. `[LinuxFact]` tests skip off Linux.
  - The `.deb` (`clients/helper/packaging/linux/`) installs the self-contained, not single-file, helper and `healdan.oxt` in `/opt/healdan-helper/`, with a desktop entry for `x-scheme-handler/healdan` and an autostart entry. Its `Depends` include `libicu78`, which ties it to Ubuntu 26.04, and `libsecret-tools`, `libnotify-bin`, `xdg-utils` and `libreoffice-script-provider-python`. The autostart entry has `TryExec`, so after a removal that keeps it (a conffile) nothing starts. `package.sh` drops .NET's `libcoreclrtraceptprovider.so`, which needs `liblttng-ust.so.0`, absent from 26.04, and loads only with LTTng tracing on. There's no HarfBuzz workaround: the trial's start-up crash didn't recur.
  - The helper's macOS icon is the docs site's `site/static/favicon.svg` on macOS's rounded square, which `clients/helper/packaging/mac/make-icon.swift` draws each time `package.sh` runs. Changing the favicon changes it too, and fails `MarkTests` until About's mark (`Windows/HealdanMark.axaml`) is redrawn.
  - The menu bar icon is the same mark, drawn in one colour at run time from `HealdanMark`'s shapes (`Tray/TrayIcons.cs`), so it follows the favicon with About's mark.
  - The helper's icons are Tabler's, in `clients/icons/tabler/`. `python3 clients/icons/write-helper-icons.py` writes `HelperIcons.axaml` from them, and `IconsTests` fails until it's run after an icon is added or changed. A new icon also goes in `IconsTests`' `SpecNames`, the spec's list.
  - The extension's toolbar and menu images are in `clients/libreoffice/healdan/icons/`, rendered from the helper's icons and mark by `clients/helper/tools/IconRender` (outside the solution, so CI doesn't build it; run it by hand on a Mac after an icon changes, and commit the output). The package's own `THIRD-PARTY-NOTICES.txt` carries Tabler's licence. Bump `description.xml`'s version when the extension's content changes: the helper installs only a newer one over an installed copy.
  - `clients/helper/Healdan.Helper/THIRD-PARTY-NOTICES.txt` is About's Open-Source Notices. `NoticesTests` fails when its `Packages:` lines and the packages the helper restores differ, ids and versions both, so a package added or moved needs its notice.
