# Healdan Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Healdan's own docs site at `https://docs.healdan.com`, built from `site/` with Hugo and Hextra in Healdan's colours. It launches with the Install and Developer manuals and the M1 and M1.5 User and Admin pages, and then the app and repo stop linking to LogicalDOC's docs.

**Architecture:**
- **Site.** A Hugo site in `site/`, with the Hextra theme vendored in `site/_vendor/`. Each manual is one top-level content folder with `cascade: { type: docs }`.
- **Healdan's own files.** A CSS file for the colours and boxes, an i18n string for the copyright line, and three templates: the phone-menu override, the footer links and the `interim` shortcode.
- **Checks.** Stdlib Python scripts in `.github/scripts/` check the site's sources and its built links. Their unit tests, and a build test of `site/`, run in a new `Docs site` workflow, which also deploys to GitHub Pages once `DOCS_PUBLISH` is on.
- **Link switch.** After go-live, the app's Help link moves to docs.healdan.com through `HealdanSystemInfo`, which Healdan already owns. A repo-wide check then stops new links to LogicalDOC's docs.

**Tech Stack:**
- Hugo 0.168.0, standard edition, not extended.
- Hextra v0.13.0, a Hugo module, vendored.
- Python 3 standard library only (`unittest`, `html.parser`, `subprocess`).
- GitHub Actions and GitHub Pages.
- For PR C: JUnit 4 in `healdan-core`.

**Status:** the owner approved this plan, including its spec corrections, on 2026-10-23, and chose native execution in one session. PR A (#59) and PR B (#60) are merged, and the site is live. PR C (Tasks 14–17, #61) merged on 2026-10-24. Task 18's row 8 waits for the owner, on a stack built from `master`, and so does Task 13's row 5 (see the decision log).

**Spec:** [`docs/superpowers/specs/2026-10-23-docs-site-design.md`](../specs/2026-10-23-docs-site-design.md), approved by the owner on 2026-10-23. Every § below points there. Read it first; this plan doesn't repeat its reasons.

## Global Constraints

Every task's requirements include these.

- **Where things live.** The site's source is `site/`; nothing for the site goes under `docs/`, which stays internal. The base URL is `https://docs.healdan.com/`.
- **Versions.** Hugo `0.168.0`, the standard `hugo_0.168.0_linux-amd64.tar.gz` build, never extended. Hextra `github.com/imfing/hextra v0.13.0`, vendored by `hugo mod vendor`. Building needs no Go and no network.
- **Builds are strict.** Every build runs `hugo --source site --gc --minify --panicOnWarning`. Two deprecations already fail it:
  - write `locale: en-GB`, never `languageCode`;
  - give each tab its name with `{{< tab name="…" >}}`, never `{{< tabs items="…" >}}`.
- **Colours** (spec §5.2):
  - `--primary-hue: 209deg; --primary-saturation: 88%; --primary-lightness: 40%`.
  - `#22a2e0` is never text on a light background.
  - In dark mode, links and highlights are `#4aa8f0` or lighter, and the headline gradient starts at `#4aa8f0`, not `#0b5dab`.
- **Wording** (spec §6.3):
  - Title Case, with Chicago small words, for titles, `linkTitle`s, headings, card and tab labels, buttons and footer links.
  - Body text in sentence case.
  - British spelling.
  - Healdan's glossary terms.
  - A front-matter value containing ` #` is quoted, and a heading that ends in `#` ends in `\#`.
- **No LogicalDOC text or screenshots,** and no page about something that isn't on `master`. "Using a Published Image" waits until images are published (spec §6.1).
- **Fixed copy** (exact, spec §5.4 and §6.2):
  - Copyright, line 1: `© 2026 The Healdan Project. This documentation is licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); Healdan's code is licensed under the [LGPL-3.0](https://github.com/Healdan-Project/healdan/blob/master/LICENSE).`
  - Copyright, line 2: `Healdan is a modified version of [LogicalDOC Community Edition](https://www.logicaldoc.com), © 2006-2027 LOGICALDOC Srl. LogicalDOC is a trademark of LOGICALDOC Srl, which doesn't endorse Healdan.`
  - Interim box, first line: `This page isn't written yet. Until it is, LogicalDOC's <title> covers similar ground.`
  - Interim box, second line: `LogicalDOC's docs describe its Enterprise edition, so some features there aren't in Healdan, and their workspace isn't a Healdan Workspace.`
- **Upstream edits.** Only in PR C, and only those in Task 16. CI files and `.github/scripts/` are Healdan's own.
  - Several upstream files have CRLF line endings, including `RestAuthService.java` and some `messages_*.properties`. Edit them byte-preserving (Python `newline=''`, or bytes), never with a tool that rewrites line endings.
  - Java sources stay ASCII.
- **Actions are pinned by major tag,** as the existing workflows do: `actions/checkout@v7`, `actions/upload-artifact@v7`, `actions/upload-pages-artifact@v5`, `actions/deploy-pages@v5`.
- **Commits** follow the repo's style: a plain-English summary line, a body saying why, and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

These five conditions are what the spec implies and the task tests would otherwise miss. Each is pinned by a test in the task named.

1. **Help opens `https://docs.healdan.com/?lang=de`,** because `MainMenu.java:685` appends the locale. The page must load as if the query weren't there. Task 1's link checker ignores query strings (`test_query_string_ignored`), and Task 13 opens the address with `?lang=de`.
2. **A mistyped or retired address** must show Healdan's 404 page, not GitHub's or Hextra's. Task 2 (`test_404_page_is_healdan`) and Task 13.
3. **Before go-live,** `DOCS_PUBLISH` is unset. A push to `master` must skip the deploy job, not fail it, so `master` stays green. Task 7 checks the first `master` run after PR A merges.
4. **An upstream sync brings a new `docs.logicaldoc.com` link.** The build must fail with the file, the line and the fix, as the icon check does. Task 14 (`test_reports_file_line_and_fix`).
5. **A manual's own landing page** (`/admin/`) and a deep page (`/user/finding-documents/finding-by-doc-number/`) must both highlight their manual's tab and show only that manual's nav. Task 2 (`test_current_manual_tab_is_highlighted`) and Task 4.

## Spec corrections and calls this plan makes

The owner approves these with the plan. The spec gets a short note pointing here when PR A merges.

1. **The Help URL changes in `HealdanSystemInfo`, not `SystemInfo.java`** (spec §10.1).
   - `healdan-core` already declares the only `SystemInfo` extension (`HealdanSystemInfo`, checked by `HealdanSystemInfoTest`). `InfoServiceImpl.java:260` copies its help URL into the GUI, and `SoapSystemService.getInfo` copies it into `WSSystemInfo` with `BeanUtils.copyProperties`.
   - So `SystemInfo.java:39` and `WSSystemInfo.java:31` are defaults that Healdan's object always replaces. They stay unedited, and the link check allows exactly those lines. That's two fewer upstream edits.
   - `GUIBranding.java:47` is edited, because M1 already made its other defaults match `HealdanSystemInfo`'s.
2. **The forum link doesn't change.** `HealdanSystemInfo` has set `forum = "-"` since M1, which hides Help > Forum. The SOAP API returns `-` too. `WSSystemInfo.java:40` is a replaced default (correction 1).
3. **No `-Dtest` addition.** The new assertions live in `HealdanSystemInfoTest`, a `healdan-core` test CI already runs.
4. **The link check is split in two.** `check-site-sources.py` (Task 1) enforces "LogicalDOC doc links only inside `interim`" for `site/content/`, from PR A on. `check-logicaldoc-doc-links.py` (Task 14) covers the rest of the repo, the rest of `site/` included, and skips `site/content/` and `site/_vendor/`. Together they enforce what spec §10.3 describes.
5. **The link checker is a stdlib Python script,** matching `check-fontawesome-icons.py`, so there's no binary to pin. Hugo comes from its release tarball, checked against the release's checksum file.
6. **The scripts get unit tests** in `.github/scripts/tests/`, a new folder. A build test (`test_site_build.py`) pins the landing page, the nav, the footer, the favicons and the 404 page, so a Hextra upgrade that breaks the overrides fails CI.

## Conventions

- **Run the script tests:** `python3 -m unittest discover -s .github/scripts/tests -v`. `test_site_build.py` needs `hugo` on the `PATH`. If it's missing, it skips locally and fails when `CI` is set.
- **Preview the site:** `hugo server --source site`. The server doesn't fingerprint CSS, so after a CSS change force-reload, or restart the server, before judging a page.
- **Show the owner:** start the preview from `.claude/launch.json` with `preview_start` and use the browser pane, as the spike was shown. `.claude/launch.json` is untracked; never commit it.
- **The spike** is in `.superpowers/docs-site-spike/`, which git ignores. It's throwaway: copy from it only what this plan specifies, and re-check what you copy.
- **Stacked PRs** target `master` (CI only runs there). PR B starts from `master` after PR A merges.

  - `check-site-links.py`: `find_broken_links(public: pathlib.Path, base_url: str) -> list[str]`, then `main(argv) -> int`. Usage `check-site-links.py <public dir> [--base-url URL]`, defaulting to `https://docs.healdan.com/`. Each problem reads `<page relative to public>: <href>: <why>`. Same exit codes.
- Both start with a header comment like `check-fontawesome-icons.py`'s: what's checked, usage and exit status.

- [ ] **Step 1: Write the failing tests**

`test_check_site_sources.py` writes fixture Markdown into a temporary `content/` folder:

- `test_heading_ending_in_hash_reported`: `## Legacy Doc #` gives one problem containing `\#`. `## Legacy Doc \#` gives none, and neither does a `## …#` line inside a fenced code block.
- `test_logicaldoc_doc_link_outside_interim_reported`: `[guide](https://docs.logicaldoc.com/en/installation)` gives one problem containing `interim`. Lines containing `{{< interim href="https://docs.logicaldoc.com/en/installation" title="Installation Guide" >}}`, `https://www.logicaldoc.com` or `ws.logicaldoc.com` give none. The pattern is `https?://(docs|wiki|help|forums)\.logicaldoc\.com`.
- `test_clean_site_exits_zero`: `main([str(tmp)])` returns 0 for a clean fixture, and 1 for a bad one.

`test_check_site_links.py` writes fixture HTML into a temporary `public/`:
- `test_missing_page_reported`: `/missing/` from `index.html` is reported.
- `test_directory_link_resolves_to_index`: `/install/` resolves when `install/index.html` exists.
- `test_relative_link_resolved`: `../admin/` from `install/quick-start/index.html` resolves to `admin/index.html`.
- `test_missing_anchor_reported`: `/user/#nope` is reported. `/user/#go-straight` resolves when that page has `id=go-straight`. Minified HTML has unquoted attributes, so test those. `#local` resolves against the same page.
- `test_assets_checked`: a missing `<img src=/images/x.png>`, `<script src>` or `<link href>` is reported.
- `test_query_string_ignored`: `/user/?lang=de` resolves.
- `test_base_url_links_are_internal`: `https://docs.healdan.com/admin/` is checked like `/admin/`.
- `test_external_and_special_links_ignored`: `https://example.org/x`, `mailto:`, `tel:`, `javascript:` and `data:` aren't checked.
