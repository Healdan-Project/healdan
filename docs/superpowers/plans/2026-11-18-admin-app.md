# The Admin App: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Admin app's first version: an app at `/admin/`, for administrators only, that runs clients, matters and their workspaces, storage, people, monitoring and reindexing, with no edit to any upstream file.

**Architecture:**
- **`healdan-web`** gains `apps/admin` beside `apps/user`, a shared `packages/shell`, and `AdminAppServlet`, which refuses everyone but administrators before it looks at a file.
- **`healdan-api`** gains `/api/v1/admin/*` in `com.logicaldoc.healdan.api.admin`, behind `AdminFilter`, with its own contract, `openapi-admin.yaml`.
- **`healdan-core`** gains `com.logicaldoc.healdan.admin`: the administration record, error capture, job status, the usage summary, the transactional services the routes call, and the reindex worker.
- **`healdan-storage`** implements `StorageAdministration`, an interface in `healdan-core`, over its unchanged `StorageAdmin`.

**Tech Stack:** Java 25, Spring 6.2, Hibernate 7, Flyway, CXF 4 JAX-RS, Log4j 2.24, JUnit 4 (`AbstractHealdanTestCase`, `ApiTestCase`) on PostgreSQL 18. React 19, TypeScript, React Aria Components through `@healdan/ui`, TanStack Query and Router, Vite, Vitest, Testing Library, Playwright.

**Spec:** [`docs/superpowers/specs/2026-11-18-admin-app-design.md`](../specs/2026-11-18-admin-app-design.md), with its [mockups](../specs/2026-11-18-admin-app-mockups/README.md). Every task's implementer reads the sections its task names. Where a mockup and the spec differ, the spec wins.

**Status:** written on 2026-11-18, after the spec's approval, and approved by the owner the same day for subagent-driven building. Phase 1 (Tasks 1 to 12) built on 2026-11-19, in pull request `Admin app: the foundation and the Dashboard`; its departures from this plan are in the [Decision Log](#decision-log). Phases 2 to 6 not built.

## Global Constraints

Every task's requirements include these.

- **The start condition.** Nothing starts until the PostgreSQL work's PR A has merged: `healdan-core/src/main/resources/healdan/db/migration/postgresql/V11__trash.sql` and `com.logicaldoc.healdan.util.Savepoints` are on `master`. Task 1 checks.
- **No upstream edit.** No file in a `logicaldoc-*` module, the root `pom.xml` or `.gitignore` changes (spec §15.1). A task that finds it can't avoid one stops and asks the owner.
- **Who gets in.** Members of the `admin` group only. A device token never reaches an admin route. Every admin route carries `@AdminRoute`.
- **Nothing secret** in a response, a log line, the administration record or an export: S3 secrets, provider client secrets, passwords and recovery keys, but for Show Recovery Key and a temporary password shown once.
- **Anything that can grow long is a search:** matters, clients and people, in forms and in filters. Stores and workspace templates stay plain menus.
- **The SQL rules** (PostgreSQL spec §7.3 and §7.4, and that plan's Global Constraints):
  - no statement is expected to fail inside a transaction, and one that may fail without failing its caller runs in `Savepoints.run`;
  - a flag is an `int` column and field, never `boolean`;
  - SQL given to CE's DAO helpers never uses `::`; write `cast(x as text)`;
  - every `order by` on a nullable key says where NULLs go, through `ListingSql.nullsLast`;
  - a typed value that's compared is trimmed in Java;
  - nothing relies on whole-second times.
- **While the PostgreSQL switch (PR B) hasn't merged,** SQL also runs on MariaDB: no `on conflict`, nothing else PostgreSQL-only or MariaDB-only, no SQL `nulls first` or `nulls last`.
- **Migrations.** A new script takes the next free version, in every folder of `healdan-core/src/main/resources/healdan/db/migration/` that then exists, with the same name. PostgreSQL's copy follows the five translations of that plan's Task 1, and an inline `unique index` becomes `create unique index` after its table. A migration added here moves PR B's planned `V12__widen_logicaldoc_text.sql` to the next number, and `PostgresMigrationsTest`'s count, the move's expected version and its fixture follow. Scripts carry no licence header and never change once shipped.
- **Addresses** use none of the segments `login`, `setup`, `frontend`, `license`, `sessions`, `mobile`, `view`, `webform`, `sc` or `ace`, none starting `info`, and no trailing slash but `/admin/`.
- **No new runtime npm package.** Charts are plain SVG.
- **Words.** Labels are US English and Title Case, in `apps/admin/src/strings/en-US.ts`. Docs are British, quoting labels in bold as the app shows them (the Developer Guide's Writing Docs page).
- **Licence headers:** every new source file opens with the two SPDX lines in its own comment syntax, year 2026.
- **Docs change in the pull request that ships what they describe** (spec §16).
- **The public repository.** Commits, pull requests and docs name no address of the owner's server, and describe no weakness in the Classic Interface's services.

## Review Focus

What the spec implies and a task's happy path wouldn't meet, most likely first. Each has its test in the task named.

1. **An administrator removed from `admin`, or signed out, while the app is open.** A person expects the next call to be refused, the page to say so, and no data to keep arriving (Task 4, Task 5, Task 11).
2. **Locking everyone out.** Disabling or demoting the last enabled administrator, oneself, or two administrators doing it to each other at once. A person expects one to be refused (Task 26).
3. **Secrets and hostile text in records and exports.** A changed S3 secret in the audit detail, a new password in a log, and a name such as `=HYPERLINK(…)` opened from the CSV in a spreadsheet. A person expects none of them to do harm (Task 6, Task 22, Task 31).
4. **A storm of errors, or errors while the database is down.** A person expects requests to go on working, the server not to fill its memory, and the Errors screen to catch up (Task 7).
5. **Documents changing under a reindex:** one deleted, moved, checked out or replaced mid-run, the scope's folder deleted, and a restart. A person expects the job to carry on, reach its end and say what it couldn't do (Task 34).

## Spec Corrections and Calls This Plan Makes

1. **New Store in Phase 2 has no backend field** (spec §8.6, §14). A new Store starts on Original, as it does today. Tasks 23 and 24 add the backend field, when the storage port can write.
2. **The admin types are named exports of `@healdan/api`,** `adminPaths` and `adminComponents`, not a separate package entry (spec §9.2). They're types only, so nothing reaches a bundle, and `@healdan/api` has no `exports` map to extend.
3. **`/v1/admin/find` ships in Phase 1 with clients and people,** and matters' part reads `MatterDAO` directly, ahead of Phase 2's screens.
4. **Reindex jobs run one at a time, oldest first,** and the worker is a `HealdanStartListener` with a `runOnce()` for tests, as other workers are.
5. **The usage summary counts a matter's documents from the properties stamped on them** (`HealdanConstants.ATTR_CLIENT`, `ATTR_MATTER`) in `ld_document_ext`, the same stamps M6's filters read, so no folder walk is needed.
6. **The Server Log's Download is a zip** of the chosen log and its rolled files, as the Classic Interface's is.

## Conventions

- **Server tests** need the test database: `docker/tests/test-db.sh start`, then `HEALDAN_TEST_DB_URL=jdbc:postgresql://localhost:5432/` in the environment. A Maven container uses `--network healdan-test` and `jdbc:postgresql://healdan-test-db:5432/`.
- **Module order.** After changing `healdan-core`: `mvn -B -ntp -pl healdan-core -DskipTests install`, which also installs its test-jar, then run `healdan-api`'s or `healdan-storage`'s tests.
- **Server test bases:** `AbstractHealdanTestCase` with `HealdanFixtures` (`user`, `group`, `store`, `client`, `matter`, `storeTemplate`, `folder`, `searchFolder`, `grant`, `upload`, `admin`); `ApiTestCase` with `get`, `post`, `patch`, `put`, `delete` and `ApiCall.webSession(signInWeb(user))`.
- **Web checks,** from `healdan-web/web`: `npm ci --ignore-scripts`, `npm run generate`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
- **Each screen task** tests with Vitest and Testing Library over `AD/test/fakeApi.ts`, typed from `openapi-admin.yaml`, and calls `expectNoAxeViolations` on what it draws.
- **Each phase ends with a task** that adds its Playwright specs and docs, and opens its pull request.
- Commit after each task with a message in the repository's style: `Admin app: …`.
