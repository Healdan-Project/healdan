# M6 "New web UI: User app" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The User app, served at `/app/`, in which the owner does a whole working day (the Daily Driver), built as the foundation that later phases, the Walls app and the Admin app grow on, as the approved spec describes.

**Architecture:**
- **`healdan-web`**, a new JPF plugin module (`com.logicaldoc.healdan.app`), holds an npm workspace (`healdan-web/web/`: `packages/ui`, `packages/api`, `apps/user`) that `frontend-maven-plugin` builds into the jar, and `AppServlet`, which serves it at `/app/*` with its own Content-Security-Policy and sends a browser without a web session to `login.jsp` with a checked return path.
- **`healdan-api`** gains a second way in, the web-session route in `TokenFilter` (Fetch Metadata: same-origin always, `X-Healdan-Client: web` for changes, the HTTP session's `sid` only), and the endpoints the app needs: sign-out, My Matters, recent emails and clients, suggestions, rename, move, delete, preview, the email view and filters with honest counts on search and folder listings.
- **`healdan-core`** gains the landing rule (`ui.start`, `ReturnPath`, `LoginLandingFilter`), folder listings paged, sorted, filtered and counted in SQL, search paged past Solr's 1,000-row default with counts over the readable hits, the file kinds, the email body's cleaning with jsoup and the preview state.
- **The old UI** gets one hook: an **Open in Healdan** button in its menu bar.

**Tech Stack:**
- **Server:** JDK 25, CXF 4 JAX-RS, Spring 6.2, Hibernate 7, Flyway, jsoup (already in `logicaldoc-util`), JUnit 4 with Spring's servlet mocks, as M2 to M5. No new Java libraries.
- **Build:** `frontend-maven-plugin` (`com.github.eirslett`, Apache 2.0) with Node 24 LTS.
- **App, at runtime:** React 19, React DOM, React Aria Components, TanStack Query 5, TanStack Router 1, `pdfjs-dist`, `@tabler/icons-react`. Nothing else.
- **App, building and testing only:** Vite, TypeScript, Vitest, jsdom, Testing Library, axe-core, ESLint (with `typescript-eslint`), openapi-typescript, Playwright.
- **Versions:** each npm package and Node at its newest release on the day Task 2 starts, pinned exactly; the decision log records them.

**Spec:** [`docs/superpowers/specs/2026-11-10-m6-user-app-design.md`](../specs/2026-11-10-m6-user-app-design.md), with its [mockups](../specs/2026-11-10-m6-mockups/README.md). Read it with this plan: tasks cite its sections.

- **The web-session route's rule** (spec §8.1), exactly: no `Authorization` header; `Sec-Fetch-Site: same-origin`; `Origin`, when present, equal to `PublicAddress`'s origin or, without one, the request's own scheme and host; `X-Healdan-Client: web` on `POST`, `PATCH`, `PUT` and `DELETE`; an open CE session id in the HTTP session's `sid` attribute (`SessionManager.PARAM_SID`), never from a parameter, a header or the `ldoc-sid` cookie. Refusals are `401 unauthenticated`.
- **The return path** (spec §8.3): starts with `/app/`; no `//`; only `[A-Za-z0-9/._~%?&=-]`, which leaves out every scheme's `:`, `\`, quotes and `<`; at most 2,000 characters. Anything else is `/app/`.
- **`AppServlet`'s policy** (spec §7.2), exactly: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self' data:; worker-src 'self'; connect-src 'self'; frame-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`.
- **The email body's policy** (spec §9.4): `sandbox allow-popups allow-popups-to-escape-sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:` plus ` https:` with `pictures=true`; `font-src data:; frame-ancestors 'self'`.
- **Nothing unreadable** appears in a list, a suggestion, a count or a `#` answer. Every check goes through `AccessChecks` (CE's search permission rule, `getDeniedDocIds`, differs from it and isn't used).
- **Strings:** every string the app shows is in `packages/ui/src/strings/en-US.ts`, in US English and Title Case for labels (spec §5, §10.4).
- **No secret or document data in browser storage.**
- **Licence headers** (CLAUDE.md) on every new source file, Java, TypeScript, TSX, CSS, HTML, shell, Python and config written in TypeScript or JavaScript, with 2026; none on `package.json`, `package-lock.json` or the Flyway scripts.
- **Docs ship in the task that changes the behaviour** (CLAUDE.md). Title Case for titles, headings and labels; British spelling in prose; app labels quoted exactly as the app shows them, in US English (Task 8 adds the rule to Writing Docs).
- **CI time.** Each PR states how many seconds it adds to `build`, the `Tests` jobs, `Web`, the Docker smoke test and `Clients`.

## Review Focus

These are the inputs most likely to hurt someone that a task's main tests could miss. Each has a test in the task named.

1. **A request from another site acting through someone's web session:** a cross-site `POST`, a same-site but cross-origin request, a request with no `Sec-Fetch-Site`, `sid` smuggled as a parameter, a header or the `ldoc-sid` cookie (Task 3).
2. **A return path that writes script into `login.jsp`:** quotes, `</script>`, a scheme, `//host`, a backslash, percent-encoded tricks, an over-long path (Task 4).
3. **A count, a suggestion or a `#` answer revealing a document the caller can't read:** a privileged folder, a document with its own ACL, an unpublished document (Tasks 9, 10, 11, 14).
4. **An email body running script, submitting a form, framing the app or loading a tracker** without Show Pictures (Task 17).
5. **A drop filing into the wrong place or twice:** a matter's top level, a search folder, a second drop of the same email, a drop on a row while the document is held by someone else (Task 19).
6. **A dependency slipping in** with a licence outside the list, or an install script running (Task 2).

## Spec corrections and calls this plan makes

The owner hears about these when this plan is handed over. Task 22 folds them into the spec, each marked "changed in the build". *Done in PR E: each is in the spec at its section, with the build's rulings.*

1. **The module's Java is in `com.logicaldoc.healdan.app`,** not `com.logicaldoc.healdan.web` (spec §7.1): `healdan-core` already has `com.logicaldoc.healdan.web` (`PublicAddress` and its GWT RPC servlets). The jar's files are under `healdan/app/user/`.
2. **Facets are counted in SQL over the hits that pass the read check** (spec §9.2, §12). The survey answered the trial's second question: CE's Solr search handler has its `facet` component commented out (`solrconfig.xml`), and CE copies `solrconfig.xml` into an install's index folder only when none is there, so a fix would never reach existing installs. Of §9.2's two ways only the first works. Task 10 measures it on a bulk-loaded stack and sets the counting window, in place of the second trial.
3. **Search filters split between Solr and SQL.** Author, Class, Client and Matter go to Solr as filter queries on `ext_author` (the username), `ext_docclass`, `ext_client` and `ext_matter`, which are untokenized strings. File Type and Edit Date filter in SQL, since Solr has no type field and its `date` is `ld_date`, not the edit date. *Task 10 found CE's index holds no `ext_*` fields at all, so all six filter in SQL; see the decision log.*
4. **Paging past 1,000 needs `rows` to reach Solr.** CE's `FulltextSearch` passes no `rows`, so the handler's default of 1,000 applies whatever `setMaxHits` says. Task 10's first step proves whether Healdan's search classes can pass it without an upstream edit (through `StandardSearchEngine.search(expr, filters, lang, rows)`). If not, it stops and asks the owner for a one-line upstream edit in `FulltextSearch` passing `options.getMaxHits()`, listed in spec §14.1 with `FulltextSearchTest` in `UPSTREAM_TESTS`.
5. **The licence check runs in `build`'s `checks` job,** beside the other checks, not in `Web` as well (spec §7.3 and §7.4 said both).
6. **Development-only packages may also carry** BlueOak-1.0.0, CC0-1.0, CC-BY-4.0, Python-2.0 or Unlicense (spec §7.4). Packages marked `dev` in the lockfile never ship; Vite's and ESLint's trees carry these. Runtime packages keep the strict list.
7. **Titles sort by `ld_filename`, doc #s numerically by a cast** (spec §6.1). CE has no title column, and `ld_customid` is `varchar(200)`. The SQL follows the PostgreSQL rules in the S3 plan's Global Constraints, so the cast is written for both MariaDB and HSQLDB through one helper.
8. **On the web-session route, `Caller.token()` is null.** `GET /auth/tokens` marks no token `current`, and `DELETE /auth/tokens/current` answers `403 token-only`.
9. **`.dockerignore` gains `**/node_modules`,** so a developer's local install never reaches the image's build context.
10. **The bulk loader is kept** (`docker/tests/bulk-documents.sh`): Task 9 writes it for its paging measurement, Task 10 for the counting window, and the owner's walkthrough row 4 uses it for the 2,000-document folder.
11. **The `Web` check becomes required in master's ruleset by the owner's hand** (a repository setting), once Task 2's pull request has run it once.

## Conventions

- **Running Maven:** `mvn -B -ntp -pl healdan-core install -DskipTests`, then `mvn -B -ntp -pl healdan-core test -Dtest=<Class>` or `mvn -B -ntp -pl healdan-api test -Dtest=<Class>`. `healdan-api`'s tests need `healdan-core` installed with `-DskipTests` (its test-jar), and are best run in one reactor, `mvn -B -ntp -pl healdan-api -am package -Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false -Dgwt.skipCompilation=true -Dmaven.antrun.skip=true -Dhealdan.web.skip=true`, as parallel sessions share `~/.m2`. `~/logicaldoc-dev.properties` must exist (an empty file works).
- **`healdan-web`'s Java tests:** `mvn -B -ntp -pl healdan-web -am test -Dtest=<Class> -Dsurefire.failIfNoSpecifiedTests=false -Dgwt.skipCompilation=true -Dmaven.antrun.skip=true -Dhealdan.web.skip=true`.
- **The app:** in `healdan-web/web/`, `npm ci --ignore-scripts`, then `npm run generate`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. One test file: `npx vitest run packages/ui/src/components/Button.test.tsx`.

- **Users in tests:** the app's end-to-end tests sign in as `webuser`, a non-admin user added to the smoke fixture by Task 8, never as `apiuser`, whom `test-api.sh` leaves blocked for 15 minutes.

```java
static Optional<String> resource(String pathInfo) {
	if (pathInfo == null || pathInfo.isEmpty() || "/".equals(pathInfo))
		return Optional.empty();
	String path = pathInfo.substring(1);
	if (path.contains("..") || path.contains("\\") || path.indexOf('\0') >= 0 || path.startsWith("/"))
		return Optional.empty();
	if (!path.matches("[A-Za-z0-9._/-]+"))
		return Optional.empty();
	return Optional.of(ROOT + path);
}
```

- `doGet`: decide by the last path segment: with a `.` it's a file (serve or `404`), without it's an address (serve `index.html`). Hashed files (a segment matching `-[A-Za-z0-9_-]{8,}\.`) get the immutable cache header; every other file and `index.html` get `no-store`.

DEV_ALSO = {"BlueOak-1.0.0", "CC0-1.0", "CC-BY-4.0", "Python-2.0", "Unlicense"}
ALLOWED = {
    # "node_modules/<name>": "why it's acceptable",
}

def acceptable(expression, allowed):
    expression = expression.strip().strip("()")
    if " OR " in expression:
        return any(acceptable(part, allowed) for part in expression.split(" OR "))
    if " AND " in expression:
        return all(acceptable(part, allowed) for part in expression.split(" AND "))
    return expression in allowed

def problems(lock):
    found = []
    for key, entry in lock.get("packages", {}).items():
        if "node_modules/" not in key or key in ALLOWED:

        licence = entry.get("license")
        allowed = STRICT | DEV_ALSO if entry.get("dev") else STRICT
        if not licence or not acceptable(licence, allowed):
            found.append(f"{key}@{entry.get('version')}: {licence or 'no licence'}")
    stale = [key for key in ALLOWED if key not in lock.get("packages", {})]
    return found + [f"{key}: in ALLOWED but not in the lockfile" for key in stale]
